EXECUTIVE SUMMARY
Future Pathways is a production-quality career-guidance SaaS built on a React/Express/PostgreSQL stack. The codebase demonstrates solid security awareness: Helmet CSP, CSRF double-submit cookie, bcrypt password hashing, AES-256-GCM credential encryption, rate limiting on all sensitive endpoints, Stripe webhook signature verification, path-traversal protection on file downloads, and Zod input validation throughout. These are genuine strengths that exceed typical Replit-originated projects.

However, three bugs qualify as production blockers. First, the OAuth callback URL falls back to a Replit .repl.co domain when BASE_URL is unset — Google and Microsoft login will fail silently in production. Second, when a user deletes their account, the code calls res.clearCookie("connect.sid") but the session is actually named fp_session, so the auth cookie is never cleared. Third, VITE_STRIPE_PUBLIC_KEY must be present at npm run build time, but it is listed only as optional; a misconfigured CI pipeline will deploy a payment-broken build with no runtime warning.

Several high-priority issues follow: four npm audit vulnerabilities (including one high-severity esbuild path through drizzle-kit), a permanent unsafe-inline directive in CSP's styleSrc, the superadmin email address hardcoded in the committed .replit file, and organizationMembers rows orphaned by the GDPR account-deletion route. The overall production readiness is Conditional Pass — the blockers are small and fixable, but must be resolved before any production deployment.

🔴 CRITICAL — Production Breakers
FINDING C-1: OAuth callback URL falls back to Replit domain if BASE_URL is unset

FILE: server/auth.ts
LINE: 104
ISSUE: const baseUrl = process.env.BASE_URL || `https://${process.env.REPL_SLUG}.${process.env.REPL_OWNER}.repl.co`;
       If BASE_URL is not set in the production environment (it is listed as OPTIONAL in
       constants.ts line 68), the Google and Microsoft OAuth strategies will register their
       callback URLs pointing to *.repl.co — a Replit-only domain that does not resolve in
       production. All OAuth logins will fail with a provider-side "redirect_uri_mismatch" error.
FIX:   Move BASE_URL from ENV_VARS.OPTIONAL to ENV_VARS.REQUIRED in server/config/constants.ts.
       Alternatively add explicit startup validation: if no BASE_URL, warn and disable OAuth rather
       than silently falling back to a non-functional Replit URL.

FINDING C-2: Session cookie is never cleared on account deletion (wrong cookie name)

FILE: server/routes/user.routes.ts
LINE: 151
ISSUE: res.clearCookie("connect.sid");
       The session middleware in server/auth.ts line 36 sets name: 'fp_session', so the
       actual cookie is named 'fp_session'. The DELETE /api/users/me handler clears
       "connect.sid" (the express-session default), which does not exist. After a user
       deletes their account, their auth cookie persists in the browser. Any cached
       server-side session data may allow continued API access until the 24-hour TTL expires.
FIX:   Change to: res.clearCookie("fp_session", { path: '/', httpOnly: true });
       Also consider calling req.session.destroy() before res.clearCookie() to immediately
       invalidate the session store record.

FINDING C-3: VITE_STRIPE_PUBLIC_KEY must be set at build time but is listed as optional

FILE: server/config/constants.ts
LINE: 64
ISSUE: "VITE_STRIPE_PUBLIC_KEY" // Build-time Vite variable — must be set at build time for checkout to work
       This variable is in ENV_VARS.OPTIONAL. Vite bakes import.meta.env.VITE_* values into the
       client bundle at `npm run build` time. If the key is absent when CI runs the build,
       client/src/pages/Checkout.tsx line 20–25 silently redirects to /tier-selection and
       logs console.error. No server-side build failure occurs. The deployed production bundle
       will be permanently broken for payments with no user-facing error.
FIX:   Add VITE_STRIPE_PUBLIC_KEY to ENV_VARS.REQUIRED or add a Vite plugin/build hook that
       fails the build with a clear error when this key is absent. Document that it must be set
       as a CI/CD secret before running npm run build.

FINDING C-4: organizationMembers records not deleted during GDPR account deletion

FILE: server/routes/user.routes.ts
LINE: 108–141
ISSUE: The db.transaction() in DELETE /api/users/me deletes cvqResults, quizResponses,
       assessmentQuizzes, recommendations, assessments, and the user row. It does NOT delete
       the row from organizationMembers. The orphaned row:
       (a) permanently occupies a license slot in the organization's usedLicenses count;
       (b) retains the student's name, age, gender, grade, and studentId as PII after the
           user record is gone — a GDPR Right to Erasure violation.
FIX:   Inside the transaction, add:
         await tx.delete(organizationMembers).where(eq(organizationMembers.userId, userId));
       Do this BEFORE deleting the user row to satisfy the foreign key constraint.

FINDING H-3: CSP permanently allows unsafe-inline for all styles (weakened XSS protection)

FILE: server/index.ts
LINE: 31–33
ISSUE: styleSrc: ["'self'", "'unsafe-inline'", "https://fonts.googleapis.com"]
       The 'unsafe-inline' directive is applied to styleSrc in ALL environments including
       production. This allows CSS injection attacks via user-controlled style attributes,
       which can be used to exfiltrate data (CSS exfiltration attacks) or create convincing
       phishing overlays within the page.
FIX:   Consider using nonces (generated per-request) for inline styles rather than a blanket
       unsafe-inline. For Tailwind/shadcn components that generate styles at runtime, evaluate
       moving to a CSS-Modules approach or using a strict style-src with hash allowlists.
       At minimum, document this as an accepted risk with a justification comment.

FINDING H-4: Puppeteer runs with --no-sandbox flag

ISSUE: puppeteer.launch({ headless: true, args: ['--no-sandbox', '--disable-setuid-sandbox',
       '--disable-dev-shm-usage'] })
       Chrome/Chromium sandboxing is a critical defense layer against renderer exploits.
       While --no-sandbox is common in containers without user namespaces, in production
       environments (especially outside Replit) this may not be necessary and represents
       an unnecessary security reduction.

       process or container with no network access.

FINDING H-5: recommendations.routes.ts hardcodes localhost URL for PDF generation fallback

       In development, the Puppeteer base URL uses localhost. In production it uses
