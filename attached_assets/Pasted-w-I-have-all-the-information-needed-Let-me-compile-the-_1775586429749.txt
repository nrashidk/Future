The following aspects of the codebase are correctly and commendably implemented:

Proper server-side payment amount calculation — The client-provided amount is never trusted; prices are always calculated server-side with discount tiers applied (payment.routes.ts:34-46). Payment intent metadata stores the expected amount and is re-verified before granting premium access.

Stripe webhook signature verification — All webhook events are cryptographically verified via stripe.webhooks.constructEvent() before processing. Missing STRIPE_WEBHOOK_SECRET causes rejection, not silent acceptance.

AES-256-GCM encryption with authentication tags for stored API credentials — The implementation correctly includes IV + auth tag, preventing both decryption of tampered data and IV reuse attacks.

CSRF protection — Custom double-submit cookie pattern with SameSite: strict cookies, applied globally after auth middleware with documented exemptions.

Password strength enforcement — zxcvbn score ≥ 3 required on password reset; bcrypt with 10 rounds throughout.

Session security — Session regeneration on login, HttpOnly, Secure (production), SameSite: strict (production), PostgreSQL-backed store (no memory store), named cookie (fp_session).

Input validation — Zod schema validation applied at route boundaries; DOMPurify sanitization via sanitizeRequestBody() applied before database writes in assessment routes.
