CRITICAL VULNERABILITIES
1. Session Cookie Configuration Risk
Location: server/replitAuth.ts:49-55

cookie: {
  httpOnly: true,
  secure: true,
  sameSite: 'none', // ⚠️ CRITICAL: Allows cross-site requests
  maxAge: sessionTtl,
}

Risk: sameSite: 'none' allows cookies to be sent with cross-origin requests, exposing the application to CSRF attacks despite the CSRF token middleware.

Impact: Session hijacking, unauthorized actions

Remediation:

cookie: {
  httpOnly: true,
  secure: true,
  sameSite: process.env.NODE_ENV === 'production' ? 'strict' : 'lax',
  maxAge: sessionTtl,
  domain: process.env.COOKIE_DOMAIN, // Set explicit domain
}

6. Missing Input Validation Middleware
Location: Throughout route handlers

Current state:

Zod schemas defined for database operations
✅ Sanitization applied in some places
❌ No consistent validation middleware chain
Risk: Invalid data reaching business logic, potential injection attacks

Remediation:

// Create validation middleware
import { z } from 'zod';

export function validateBody<T extends z.ZodSchema>(schema: T) {
  return async (req: Request, res: Response, next: NextFunction) => {
    try {
      req.body = await schema.parseAsync(req.body);
      next();
    } catch (error) {
      res.status(400).json({ 
        message: 'Validation failed', 
        errors: error.errors 
      });
    }
  };
}

// Apply to routes
app.post('/api/assessment', 
  isAuthenticated, 
  validateBody(insertAssessmentSchema), // ✅ Validation enforced
  async (req, res) => { /* handler */ }
);
